## 15. 리눅스 시스템 로그파일(/var/log/messages) 점검

```
tail -1 /var/log/messages
Aug 11 23:58:50 mail kernel: device ens32 entered promiscuous mode
```

1. **해당 로그의 의미**: 네트워크 인터페이스(ens32)의 동작모드가 promiscuous mode(무차별 모드)로 변경되었음을 의미. 무차별 모드는 유입되는 프레임(패킷)의 목적지 MAC 주소와 무관하게 모든 프레임(패킷)을 수신하는 동작 모드
2. **예상할 수 있는 공격**: 네트워크 트래픽을 훔쳐보는 스니핑(Sniffing) 공격이 발생할 수 있음
3. **대응 방법**:
   - (1순위) 네트워크 스니핑을 통해 통신 내용을 알 수 없도록 암호화(보안) 프로토콜 또는 암호화 프로그램을 사용하여 통신에 사용되는 모든 데이터를 암호화
   - 허브(더미 허브) 장비에 비해 상대적으로 네트워크 스니핑 공격에 안전한 스위치(스위칭 허브) 장비를 이용
   - 스니핑 탐지 도구를 이용하여 악의적인 목적의 스니핑이 발생하는지 지속해서 점검

## 16. XSS 공격의 정의와 공격 기법 2가지

**정의**: 공격자가 공격 대상 웹 사이트에 악성 스크립트를 삽입하여 희생자 접근 시 해당 스크립트가 희생자 측에서 동작하도록 악의적인 행위를 수행하는 공격

**종류**

- Stored XSS: 취약한 웹 사이트에 악성 스크립트를 DB에 저장해 놓으면 희생자가 해당 자료를 요청했을 때 응답에 해당 악성 스크립트가 삽입되어 클라이언트 측에서 동작하는 공격 기법
- Reflected XSS: 외부에 있는 악성 스크립트(예: 악성 스크립트가 포함된 URL 링크)가 희생자의 액션(예: 클릭 등)에 의해 취약한 웹사이트에 전달되고 응답에 해당 악성 스크립트가 삽입되어 클라이언트 측에서 동작하는 공격 기법
- DOM 기반 XSS: 서버를 거치지 않고 클라이언트 측 JavaScript의 DOM 조작 과정에서 악성 스크립트가 실행되는 공격 기법

## 17. DB 접근권한 최소화

## 18. HeartBleed 취약점

1. **취약점 이름**: 하트블리드(HeartBleed) 취약점
2. **시스템적 조치 방법**: OpenSSL 라이브러리의 취약점이므로 취약점이 존재하지 않는 OpenSSL 버전으로 업데이트
3. **서비스적 조치 방법**:
   - 서버 측 SSL/TLS 개인키가 유출되었을 가능성이 있으므로 인증서를 재발급받는 것을 검토
   - 취약점에 대한 조치가 완료된 후 사용자들의 비밀번호 재생성을 유도하여 탈취된 계정을 악용한 추가 피해를 방지하는 방안을 고려
