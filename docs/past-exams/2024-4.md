## 1. 접근통제모델

- A: 주체나 그들이 소속되어 있는 그룹들의 ID에 근거하여 객체에 대한 접근 제한 → **임의적 접근통제(DAC)**
- B: 객체에 포함된 정보의 비밀성과 이러한 비밀 정보에 대하여 주체가 갖는 정형화된 권한에 근거 → **강제적 접근통제(MAC)**
- C: 역할에 따라 접근권한을 부여 → **역할 기반 접근통제(RBAC)**

## 2. RARP (Reverse ARP)

물리적인 MAC 주소를 논리적인 IP 주소로 변환해 주는 역할을 하는 프로토콜. 일반적으로 IP 주소는 시스템의 하드디스크 내 설정 파일에 저장되어 있지만, 하드디스크가 없는 터미널의 경우 초기 가동될 때 자신의 MAC 주소를 담아 RARP 요청을 만들어 자신의 IP 주소 정보를 받아오게 된다. MAC에 해당하는 IP 주소 정보를 관리하는 RARP 서버가 구성되어 있어야 한다.

## 13. 위험 분석 방법 — 복합 접근법

- **개념**: 고위험 영역을 식별하여 상세 위험 분석을 수행하고, 그 외의 영역은 기준선 접근법을 사용하는 방식
- **장점**: 위험 분석 비용과 자원을 효과적으로 사용할 수 있으며 고위험 영역을 빠르게 식별하고 적절하게 처리할 수 있음
- **단점**: 고위험 영역이 잘못 식별되었을 경우 비용과 자원이 낭비되거나 부적절한 대응이 될 수 있음

## 14. 정보보호지침 관련 구체적 내용

**정보보호 방침의 수립 및 이행**

- 정보보호 목표, 범위, 책임 등을 포함한 정보보호 방침(Policy) 수립
- 정보통신서비스와 관련된 법, 규제, 계약, 정책, 기술상의 요구사항을 문서화하고 시행

**정보보호 실행계획의 수립 및 이행**

- 정보보호 방침을 토대로 예산, 일정 등을 포함한 당해 연도의 정보보호 실행계획을 수립
- 최고경영층이 실행계획을 승인하고 정보보호 최고책임자가 추진 상황을 매 반기마다 점검

## 16. 재해복구시스템

**미러 사이트 정의**: 주센터와 동일한 수준의 시스템(IT 자원)을 원격지 사이트(재해복구센터)에 구축하여 모두 활성화(Active) 상태로 실시간 동시 서비스를 제공하는 방식으로, 주센터 재해 발생 시 즉시 재해복구센터를 통한 서비스 제공이 가능

**미러 사이트의 장단점**

- (장점) 재해 시 신속한 업무재개가 가능하고 재해 발생 시점까지 데이터 유실 없이 복구할 수 있음
- (단점) 구축 및 유지비용이 많이 들고 평상시 재해복구센터 운영방안이 필요

**RTO가 가장 긴 사이트와 그 이유**: 콜드 사이트는 데이터만 원격지에 보관하고 서비스를 위한 시스템(IT 자원)은 확보하지 않거나 장소·전원시설·통신설비 등만 최소한으로 확보하는 방식이므로, 재해 시 시스템(IT 자원)을 확보하고 데이터를 복구하는 데 많은 시간이 소요됨. 따라서 시스템(IT 자원)을 사전에 구축한 다른 사이트에 비해 복구 목표 시간(RTO)이 가장 길다.

## 17. SQL Injection 안전한 코드 작성

**안전하지 않은 코드**

```java
String gubun = request.getParameter("gubun");
String sql = "SELECT * FROM board WHERE b_gubun = "+gubun +"";
Connection con = db.getConnection();
Statement stmt = con.createStatement();
ResultSet rs = stmt.executeQuery(sql);
```

**안전한 코드**

```java
String gubun = request.getParameter("gubun");
String sql = "SELECT * FROM board WHERE b_gubun = (A)
Connection con = db.getConnection();
PreparedStatement pstmt = (B)
(C)(1,gubun);
ResultSet rs = (D)
```

**답**: (A) `?";` / (B) `con.prepareStatement(sql);` / (C) `pstmt.setString` / (D) `pstmt.executeQuery();`

## 18. NTP 서비스 DDoS 대응 방안 4가지

- 취약한 NTP 데몬 버전을 업그레이드. NTP 데몬의 버전을 확인하여 monlist 기능이 해제된 최신 버전(4.2.7 이상)으로 업그레이드
- 버전 업그레이드가 어려운 경우 설정 변경을 통해 NTP 데몬의 monlist 기능을 해제
- 점검 대상 NTP 서버가 monlist 명령을 허용하는지 여부를 점검
- 보안장비(방화벽 등)를 이용하여 100byte 이상의 NTP 서버 응답을 차단 설정
