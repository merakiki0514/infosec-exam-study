# 파트 4. 암호화 & 인증 & 접근통제

암호화와 인증은 정보보안의 기술적 기반입니다. SSL/TLS 동작 원리, 전자메일 보안, PAM, 계정 관리 솔루션이 최근 빈출입니다.

## 1. SSL/TLS 보안

> 출제 이유: SSL/TLS 핸드셰이크에서 비대칭키와 대칭키가 각각 어떤 단계에서 사용되는지가 핵심 출제 포인트입니다.

### 1-1. SSL/TLS 단계별 암호 사용 (26년도 1회)

| 단계 | 암호 방식 / 목적 |
|---|---|
| 서버 인증 단계 | 비대칭키(공개키) — CA 공개키로 서버 인증서 검증하여 서버 신원 확인 |
| 키 교환 단계 | 비대칭키(공개키) — Pre-Master Secret 생성·공유 (RSA 또는 DH 방식) |
| 암호화 통신 단계 (Change Cipher Spec 이후) | 대칭키 — 세션키+IV로 실제 데이터 암호화·복호화 |

### 1-2. 키 교환 방식 비교

| 방식 | 설명 |
|---|---|
| RSA 방식 | 클라이언트가 Pre-Master Secret 생성 후 서버 공개키로 암호화하여 전달. 서버는 개인키로 복호화 |
| Diffie-Hellman (DH) | 서버·클라이언트가 DH 공개값 교환 후 각자 Pre-Master Secret 계산. Perfect Forward Secrecy(PFS) 지원 |

**전체 핸드셰이크 순서**

1. Client Hello: TLS 버전, 암호 스위트 목록, 난수 전송
2. Server Hello: 선택된 TLS 버전, 암호 스위트, 난수 전송
3. Server Certificate: 서버 인증서 전송 → 클라이언트가 CA 공개키로 검증
4. Server Key Exchange: DH 방식 시 서버 DH 공개값 전송
5. Client Key Exchange: Pre-Master Secret 전송(RSA) 또는 클라이언트 DH 공개값 전송
6. 양측이 Pre-Master Secret으로 Master Secret 계산 → 세션키 및 IV 도출
7. Change Cipher Spec: 이후부터 대칭키 암호화 통신 시작
8. Finished: 핸드셰이크 완료 확인

!!! important "핵심"
    비대칭키 = 인증+키교환(핸드셰이크), 대칭키 = 실제 데이터 암호화. Change Cipher Spec이 전환점.

## 2. 인증서 고정 (Certificate Pinning) (25년도 2회)

> 출제 이유: 모바일 보안의 핵심 기술로, 정의·핵심요소·우회방법을 세트로 암기해야 합니다.

| 항목 | 내용 |
|---|---|
| 정의 | 모바일 앱이 통신할 서버의 SSL 인증서(또는 공개키)를 앱에 내장하여 SSL/TLS 연결 시 해당 인증서만 신뢰하도록 강제하는 기술 |
| 목적 | 중간자 공격(MITM) 방지 — 공격자가 프록시 CA 인증서를 설치해 트래픽을 가로채는 공격 차단 |
| 단점 | 서버 인증서 교체 시마다 앱 리패키징·재배포 필요 |

**핵심 요소 3가지**

1. 신뢰할 인증서(또는 공개키): 앱에 하드코딩되거나 내부 리소스에 포함된 서버 인증서
2. 검증 로직: SSL/TLS 핸드셰이크 중 서버 인증서와 고정 인증서 일치 여부 검증
3. 오류 처리: 불일치 시 연결 차단 및 사용자 알림

**우회 방법 2가지**

1. Frida/Objection 런타임 패치: SSLContext, TrustManager, HostNameVerifier 등을 후킹하여 검증 로직 우회
2. 앱 리패키징 및 재서명: 인증서 핀 고정 로직 수정 후 재패키징 (루팅 환경 필요)

## 3. 전자메일 보안 프로토콜 (25년도 4회)

> 출제 이유: PGP, PEM, S/MIME의 차이와 특징이 서술형으로 출제됩니다.

| 프로토콜 | 특징 / 설명 |
|---|---|
| PGP (Pretty Good Privacy) | 대칭키+공개키 하이브리드 방식으로 이메일 암호화 / 신뢰망(Web of Trust) 구조 — 중앙 CA 없이 개인 간 신뢰 관계 형성 / 개인용으로 널리 사용 |
| PEM (Privacy Enhanced Mail) | IETF 표준화, X.509 기반 PKI 모델 사용 / 이메일 암호화·전자서명·키 관리 제공 / 중앙 집중식 CA 기반 신뢰 구조 |
| S/MIME (Secure/MIME) | 기존 MIME 구조에 보안 콘텐츠 유형 추가 / PKI 기반 인증서로 이메일·첨부파일 암호화·전자서명 / 기업 이메일(Outlook 등)에서 표준으로 지원 |

!!! important "핵심"
    PGP=개인간 Web of Trust / PEM=IETF표준 중앙PKI / S/MIME=MIME확장 기업표준 — 이 3가지 차이를 암기하세요.

## 4. PAM (Pluggable Authentication Modules) (25년도 2회)

> 출제 이유: PAM 4가지 모듈 유형과 각 역할이 빈칸 채우기로 출제됩니다.

| 모듈 유형 | 역할 |
|---|---|
| auth (인증) | 사용자 신원 확인 — 패스워드·생체인식 등으로 인증 성공/실패 결정 |
| account (계정) | 계정 유효성 확인 — 만료 여부, 로그인 시간 제한, 허용 장소 등 |
| session (세션) | 세션 시작·종료 시 작업 — 로그 기록, 환경 설정, 홈 디렉터리 마운트 등 |
| password (패스워드) | 패스워드 갱신·변경 — 복잡도 검사, 히스토리 확인 등 |

!!! important "핵심"
    (A)account (B)auth (C)session — 빈칸 형태로 자주 출제됩니다. 각 모듈의 역할을 한 줄로 암기하세요.

## 5. 계정 관리 솔루션 EAM & IAM (25년도 4회)

> 출제 이유: EAM의 단점과 IAM으로 개선되는 사항을 구체적으로 서술해야 합니다.

| 구분 | EAM | IAM |
|---|---|---|
| 관리 대상 | 내부 시스템(서버·OS·DB·앱) 계정 중심 | 조직 전체 사용자·고객 계정까지 통합 |
| 자동화 | 수작업 기반 (운영 부담 큼) | 계정 생명주기(생성·부여·변경·회수) 자동화 |

**EAM 단점 2가지**

1. 범위가 내부 시스템·애플리케이션으로 제한되어 조직 전체 사용자·고객 계정까지 확대 적용하기 어려움
2. 수작업 기반으로 운영 부담이 크고 관리 비용 증가

**IAM 개선점 2가지**

1. EAM이 관리하던 범위를 넘어 조직 전체 사용자 계정을 단일 플랫폼에서 통합 관리
2. 계정 생성·권한부여·변경·회수 등 생명주기 전체를 자동화하여 효율성·보안성 향상

## 6. BYOD 보안 솔루션 3가지 (25년도 4회)

| 솔루션 | 설명 |
|---|---|
| MDM (Mobile Device Management) | 기업 모바일 기기를 원격으로 보호·감시 / 기능: 앱 배포, 데이터 설정 관리, 기기 잠금, 원격 데이터 삭제 |
| 모바일 가상화 (Hypervisors) | 하나의 기기에 개인용·업무용 OS를 가상화로 동시 설치 / 평상시 개인용 OS, 업무 시 업무용 OS로 전환 |
| 컨테이너화 (Containerization) | 앱 데이터를 개인용·업무용으로 분리하여 별도 보호 영역(컨테이너)에서 관리 |

## 7. 해시 함수 & 암호화 알고리즘 (26년도 1회)

| 분류 | 특징 / 알고리즘 |
|---|---|
| 대칭키 암호화 | 암호화·복호화에 동일 키 사용. 속도 빠름 / 블록: AES, DES, 3DES, SEED, ARIA / 스트림: RC4 |
| 비대칭키(공개키) 암호화 | 공개키(암호화)·개인키(복호화). 속도 느림, 키 배송 문제 없음 / RSA, ECC, DSA, ElGamal |
| 해시 함수 | 임의 길이 입력 → 고정 길이 출력. 일방향(역산 불가) / MD5(128bit), SHA-1(160bit), SHA-256(256bit), SHA-512(512bit) / 용도: 무결성 검증, 패스워드 저장, 디지털 서명 |

**해시 함수 핵심 특성 4가지**

1. 일방향성(One-way): 해시값으로 원문 복원 불가
2. 충돌 저항성(Collision Resistance): 동일 해시값을 갖는 서로 다른 입력 찾기 어려움
3. 역상 저항성(Pre-image Resistance): 해시값으로 원래 입력 찾기 어려움
4. 눈사태 효과(Avalanche Effect): 입력의 아주 작은 변화도 해시값을 크게 변화시킴

**패스워드 저장 보안**

| 방법 | 설명 |
|---|---|
| 단순 해시 | 취약 — Rainbow Table 공격에 취약 |
| Salt + 해시 | 랜덤 Salt 추가 후 해시 → Rainbow Table 무력화 |
| Key Stretching (bcrypt, PBKDF2, Argon2) | 해시를 수천~수만 회 반복 → 공격자 연산 비용 폭발적 증가 |

## 8. 패스워드 공격 기법 (25년도 4회)

| 공격 기법 | 설명 |
|---|---|
| 크리덴셜 스터핑 | 타 서비스에서 유출된 ID·PW 쌍을 다른 서비스에 대입. 비밀번호 재사용 습관 악용 |
| Password Spray | 여러 계정에 하나의 흔한 패스워드(예: Password1!) 대입. 계정 잠금 정책 우회 |
| 사전 대입 (Dictionary) | 미리 준비된 단어 목록을 순차적으로 대입 |
| 역방향 무차별 대입 | 특정 패스워드를 다수의 계정에 순차적으로 대입 |

!!! tip "TIP"
    크리덴셜 스터핑=유출DB활용 / Password Spray=계정잠금우회(패스워드고정,계정변경) / 역방향=패스워드고정 계정변경 — 3가지 구분 필수

## 9. 접근통제 모델 (24년도 4회)

> 출제 이유: 매 회차 출제되는 필수 이론. 3가지 모델의 차이를 정확히 서술해야 합니다.

| 모델 | 정의 / 특징 |
|---|---|
| DAC / (임의적 접근통제) | 주체 또는 그룹 ID에 근거하여 객체 접근 제한 / 자원 소유자가 접근 권한 임의 설정 가능 / 유연하지만 권한 관리 분산. 예: 리눅스 chmod, ACL |
| MAC / (강제적 접근통제) | 객체의 비밀성 등급과 주체의 허가 등급에 근거하여 강제 제한 / 중앙 관리자가 정책 설정, 소유자도 임의 변경 불가 / 군사·정부 기관. 예: SELinux |
| RBAC / (역할 기반 접근통제) | 사용자의 역할(Role)에 따라 접근 권한 부여 / 역할 변경 시 자동으로 권한 변경. 대규모 조직에서 효율적 / 예: ERP 시스템 부서별 권한 |

**추가: Bell-LaPadula & Biba 모델**

| 모델 | 중점 / 규칙 |
|---|---|
| Bell-LaPadula | 기밀성 중심 MAC 모델 / No Read Up(상위 등급 읽기 금지) / No Write Down(하위 등급 쓰기 금지) |
| Biba | 무결성 중심 MAC 모델 / No Write Up(상위 등급 쓰기 금지) / No Read Down(하위 등급 읽기 금지) |

## 10. Deeplink 취약점 (25년도 1회)

| 항목 | 내용 |
|---|---|
| 정의 | 모바일 앱에서 외부 URL 스킴(Custom Scheme)을 통해 앱 내 특정 화면으로 이동하는 기능 |
| 취약점 | 입력값 검증 없으면 공격자가 Deeplink URL 조작 → 비인가 화면 접근, 민감 데이터 전달, 악성 행위 유발 |
| 대응 | 수신 파라미터 엄격 검증 / 인증 필요 화면은 Deeplink 직접 접근 차단 / App Link(HTTPS 기반) 사용 |

## 11. 핵심 암기 표 — 암호화·인증

| 주제 | 핵심 키워드 |
|---|---|
| SSL/TLS 비대칭키 사용 | 서버 인증 단계 + 키 교환 단계 (Change Cipher Spec 이전) |
| SSL/TLS 대칭키 사용 | Change Cipher Spec 이후 — 세션키+IV로 실제 데이터 암호화 |
| RSA 키 교환 | 클라이언트가 Pre-Master Secret을 서버 공개키로 암호화 전달 |
| DH 키 교환 | 양측 DH 공개값 교환 → 각자 Pre-Master Secret 계산 (PFS 지원) |
| 인증서 고정 목적 | MITM 방지. 우회: Frida 런타임 후킹 / 앱 리패키징 |
| PGP vs S/MIME | PGP=Web of Trust 개인간 / S/MIME=PKI 기업 표준 |
| PAM 4모듈 | auth(인증) / account(계정유효성) / session(세션관리) / password(변경) |
| EAM→IAM 개선 | 범위 확대 (전체 계정) + 생명주기 자동화 |
| BYOD 3솔루션 | MDM / 모바일 가상화 / 컨테이너화 |
| 크리덴셜 스터핑 | 유출된 ID·PW를 타 서비스에 대입 |
| Password Spray | 여러 계정에 하나의 흔한 패스워드 대입 → 계정 잠금 우회 |
| 해시 4특성 | 일방향성 / 충돌저항성 / 역상저항성 / 눈사태효과 |
| DAC/MAC/RBAC | 소유자 자유 / 등급 강제 / 역할별 |
