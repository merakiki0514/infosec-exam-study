# 파트 5. 위험 관리 (Risk Management)

위험 관리는 정보보안기사 실기에서 매 회차 3~4문항이 출제되는 최고 빈출 파트입니다. 자산·위협·취약점의 정의, 위험처리 4가지, 위험분석 접근법 4가지를 완벽히 암기해야 합니다.

## 1. 위험 관리 기본 개념

> 출제 이유: 위험 관리의 정의와 3단계 절차는 서술형으로 자주 출제됩니다.

### 1-1. 위험 관리 정의 및 3단계 (24년도 2회)

| 항목 | 내용 |
|---|---|
| 정의 | 위험을 평가하고 조직이 수용할 수 있는 수준까지 위험 부담을 줄이는 조치를 강구하고 유지하는 일련의 과정 |
| 3단계 | 위험 분석: 조직에 존재하는 위험을 명확하게 인식·확인하는 단계 / 위험 평가: 식별된 위험의 크기를 측정하고 우선순위를 결정하는 단계 / 정보보호 대책 선정: 식별된 위험에 대응하는 보호대책을 식별·선정하는 단계 |

### 1-2. 위험 관리 6단계 (26년도 1회)

1. 위험 관리 계획 수립
2. **(A) 위험 분석**: 자산·위협·취약점 식별 및 위험 산정
3. **(B) 위험 평가**: 위험 크기 측정, 수용 가능 수준과 비교
4. 보호대책 선정: 위험 감소를 위한 대책 식별·선정
5. **(C) 정보보호 대책 구현**: 선정된 대책 실제 적용
6. 사후 관리: 대책 효과 모니터링 및 개선

!!! important "핵심"
    (A)위험분석 (B)위험평가 (C)정보보호대책 구현 — 6단계 중 이 3개가 빈칸으로 출제됩니다.

## 2. 핵심 개념: 자산 · 위협 · 취약점

> 출제 이유: 3가지 개념의 정의와 관계를 정확히 서술해야 합니다. 매 회차 출제됩니다.

| 개념 | 정의 / 설명 |
|---|---|
| 자산 (Asset) | 조직이 보호해야 할 모든 유·무형의 대상 / 예: 서버, 데이터베이스, 소프트웨어, 정보, 인력, 명성 등 |
| 위협 (Threat) | 자산에 손실을 초래할 수 있는 원하지 않는 사건의 잠재적 원인 또는 행위자 / 예: 해커, 악성코드, 자연재해, 내부자 오류 등 |
| 취약점 / 취약성 (Vulnerability) | 위협의 이용 대상이 되는 자산의 잠재적 약점 (기술적·관리적·물리적) / 예: 패치 미적용, 약한 패스워드 정책, 잠금장치 미설치 등 |
| 위험 (Risk) | 위협이 취약점을 이용하여 자산에 손실을 발생시킬 가능성 / 위험 = 자산 가치 × 위협 발생 가능성 × 취약성 수준 |

### 2-1. 손실 발생 조건 (25년도 4회)

위협이 발생하더라도 해당 취약성이 없거나, 취약성에 대한 적절한 보호대책이 마련되어 있으면 손실이 발생하지 않습니다.

즉: **손실 = 자산 + 위협 + 취약성(보호대책 부재)** 세 가지가 동시에 충족될 때 발생

### 2-2. 자산 가치 평가 — 중요도 산정 (25년도 1회)

| 항목 | 설명 |
|---|---|
| 중요도 산정 정의 | 식별된 정보 자산에 침해 사고 발생 시 다양한 측면의 영향을 파악하여 자산의 가치를 평가하는 것 |
| 필수 기준 3가지 (CIA) | 기밀성(Confidentiality): 인가된 사용자만 접근 가능 보장 — 정보 유출 측면 / 무결성(Integrity): 정보의 정확성·완전성 보호 — 정보 변조 측면 / 가용성(Availability): 인가된 사용자가 필요시 정보에 접근 가능 보장 — 서비스 제공 측면 |

### 2-3. 기밀성 평가 등급 (24년도 1회)

| 등급 | 기준 |
|---|---|
| H(상) | 매우 민감한 정보. 업무 관련 책임자만 접근 가능 |
| M(중) | 민감한 정보. 내부 담당자·책임자 등 일부 허가된 직원만 접근 가능 |
| L(하) | 민감하지 않으나 내부인만 접근 가능 |

### 2-4. 자산 그룹핑 (25년도 1회)

| 항목 | 내용 |
|---|---|
| 정의 | 자산 가치가 결정되면 유형·중요도·사용 용도·위험 등이 유사한 자산을 하나의 그룹으로 분류 |
| 이유 | 유사 자산을 그룹핑하여 동일한 위험분석·평가 작업의 반복을 방지 → 시간과 비용 최소화 |

## 3. 위험 처리(대응) 전략 4가지 (필수 암기)

> 출제 이유: 4가지 전략의 정의와 예시가 서술형으로 반드시 출제됩니다.

| 전략 | 정의 / 예시 |
|---|---|
| 위험 수용 (Risk Acceptance) | 현재의 위험을 받아들이고 잠재적 손실 비용을 감수하는 전략 / 일정 수준 이하의 위험은 감수하고 사업 진행 / 예: 보안 비용이 손실 비용보다 클 때 선택 |
| 위험 감소 (Risk Reduction) | 보호대책을 채택·구현하여 위험을 감소시키는 전략 / 비용 대비 효과 분석으로 효과적인 대책 선정 / 예: 방화벽 설치, 패치 적용, 암호화 적용 |
| 위험 전가 (Risk Transfer) | 위험의 잠재적 손실 비용을 제3자에게 이전하는 전략 / 예: 보험 가입, 외주(아웃소싱), 계약을 통한 책임 이전 |
| 위험 회피 (Risk Avoidance) | 위험이 존재하는 프로세스나 사업을 수행하지 않고 포기하는 전략 / 예: 위험한 특정 서비스 운영 중단, 위험 사업 철수 |

!!! important "핵심"
    수용=감수 / 감소=대책적용 / 전가=보험·외주 / 회피=포기 — 4가지 키워드를 각 전략에 연결하세요.

## 4. 위험분석 접근법 4가지

> 출제 이유: 복합 접근법의 개념·장단점, 상세 위험분석의 특징이 서술형으로 출제됩니다.

| 접근법 | 설명 / 장단점 |
|---|---|
| 기준선 접근법 (Baseline Approach) | 표준화된 보안 기준선(체크리스트)을 모든 시스템에 동일하게 적용 / 장점: 비용·시간 절약, 빠른 적용 / 단점: 조직 특성 미반영, 과도하거나 부족한 보안 가능 |
| 비정형(비공식) 접근법 | 전문가의 경험과 직관에 의존 / 장점: 소규모 조직에 빠르게 적용 가능 / 단점: 주관적, 재현성 없음, 전문가 의존 |
| 상세 위험분석 (Detailed Risk Analysis) | 자산 가치·위협·취약점을 체계적으로 상세히 분석 / 장점: 정확도 높음, 조직 특성 반영 / 단점: 많은 시간·비용·전문 인력 필요 |
| 복합 접근법 (Combined Approach) — 24년도 4회 | 고위험 영역: 상세 위험분석 적용 / 그 외 영역: 기준선 접근법 적용하는 혼합 방식 / 장점: 비용·자원의 효과적 사용, 고위험 영역 빠른 식별·처리 / 단점: 고위험 영역을 잘못 식별 시 비용 낭비 및 부적절한 대응 |

!!! important "핵심"
    위험분석 접근방법(전략): 기준선 접근법 / 비정형 접근법 / 상세 위험분석 / 복합 접근법 — 4가지 명칭을 모두 암기하세요.

### 4-1. 델파이법 (25년도 4회)

| 항목 | 내용 |
|---|---|
| 정의 | 다수의 전문가에게 반복적으로 설문을 실시하고, 익명으로 피드백을 주고받아 의견을 수렴하는 정성적(qualitative) 위험분석 방법론 |
| 특징 | 익명성 보장 / 반복적 피드백으로 합의 도출 / 전문가 편향 최소화 |
| 장점 | 전문가 집단의 집단지성 활용, 합의된 결론 도출 |
| 단점 | 시간이 오래 걸림, 전문가 섭외 필요 |

## 5. 정보보호 통제 분류

> 출제 이유: 예방·탐지·교정 통제와 물리·기술·관리 통제의 분류 체계가 출제됩니다.

### 5-1. 기능에 따른 통제 분류 (24년도 1회)

| 통제 유형 | 설명 / 예시 |
|---|---|

| 탐지 통제 (Detective) | 위협 발생을 탐지·식별. 예: IDS, 로그 모니터링, 감사 |
| 교정 통제 (Corrective) | 피해 발생 후 복구·교정. 예: 백업 복구, 패치 적용, 사고 대응 |

| 통제 유형 | 설명 / 예시 |
|---|---|
| 물리적 접근통제 (24년도 1회) | 물리적 침입·접근 제한. 예: 잠금장치, CCTV, 출입 카드, 보안 경비 |
| 논리적(기술적) 접근통제 (24년도 1회) | 시스템·네트워크 자원에 대한 접근 제어. 예: 패스워드, 방화벽, ACL, 암호화 |
| 관리적 통제 | 보안 정책·절차·교육 등 관리 측면. 예: 보안 정책, 직원 교육, 감사 |

## 6. 재해복구 시스템 (24년도 4회)

> 출제 이유: 재해복구 사이트 4가지 유형과 RTO/RPO 개념이 서술형으로 출제됩니다.

### 6-1. 재해복구 사이트 4가지

| 사이트 유형 | 설명 / 특징 |
|---|---|
| 미러 사이트 (Mirror Site) | 주센터와 동일한 IT 자원을 원격지에 구축하고 모두 Active 상태로 실시간 동시 서비스 / RTO: 즉시(0) / 장점: 데이터 유실 없음, 즉시 전환 / 단점: 구축·유지 비용 최대 |
| 핫 사이트 (Hot Site) | 원격지에 동일한 IT 자원 구축, 대기(Standby) 상태 유지 / RTO: 수 시간 / 장점: 빠른 복구 / 단점: 고비용 |
| 웜 사이트 (Warm Site) | 일부 IT 자원과 중요 데이터만 원격지에 보관 / RTO: 수 일 / 장점: 중간 수준 비용·복구 시간 |
| 콜드 사이트 (Cold Site) | 데이터만 원격지 보관, IT 자원은 미확보(또는 최소 인프라만 준비) / RTO: 가장 김(수 주) / 장점: 비용 최소 / 단점: 복구 시간 최대 |

!!! important "핵심"
    RTO가 가장 긴 사이트 = 콜드 사이트. 이유: 재해 시 IT 자원을 새로 확보하고 데이터를 복구하는 데 가장 많은 시간이 소요됨.

### 6-2. RTO / RPO 개념

| 용어 | 설명 |
|---|---|
| RTO (Recovery Time Objective) | 목표 복구 시간 — 재해 발생 후 서비스를 복구하는 데 허용되는 최대 시간 / 짧을수록 더 높은 수준의 재해복구 체계 필요 |
| RPO (Recovery Point Objective) | 목표 복구 시점 — 재해 발생 시 어느 시점까지의 데이터를 복구할 수 있는가 / 짧을수록(0에 가까울수록) 데이터 유실 최소화 |

### 6-3. 업무 연속성 계획(BCP)과 재해복구계획(DRP)

!!! important "기출 포인트"
    "업무 연속성 계획(BCP)과 재해복구계획(DRP)의 이름을 혼용하는 단답형 문제가 출제되었습니다. **BCP가 DRP를 포함하는 상위 개념**이라는 관계를 반드시 기억하세요."

| 항목 | 내용 |
|---|---|
| 정의 | 인재, 천재지변, 테러 등에 의한 각종 장애 및 재해로부터 업무중단이 발생할 경우 최대한 빠른 시간 내에 업무를 복구함으로써 업무 연속성을 유지하기 위한 계획(절차) |
| 범위 | IT 부문뿐 아니라 인력·설비·자금 등 조직의 모든 자원을 대상으로 장애 및 재해로부터 조직의 생존을 보장하기 위한 예방 및 복구 활동을 포함하는 광범위한 계획 |
| BCP와 DRP 관계 | DRP(재해복구계획)는 BCP에 포함되는 하위 개념으로, IT 시스템·데이터 복구에 초점을 맞춘 기술적 복구 계획 |

**업무 영향 분석(BIA: Business Impact Analysis)**: BCP 수립의 핵심 절차로, 장애·재해 시 존재하는 핵심 업무를 파악하고 업무별로 실제 사업에 미치는 영향도를 분석해 복구 우선순위를 결정하는 과정. 주요 내용:

- 주요(핵심) 업무 프로세스의 식별
- 재해 유형 식별 및 재해 발생 가능성과 발생 시 업무중단의 지속시간 평가
- 업무 프로세스별 중요도 및 재해로 인한 업무중단 시의 손실 평가
- 업무 프로세스별 우선순위 및 복구 대상 범위의 설정

**BCP의 5단계 방법론**

1. **프로젝트 범위 설정 및 기획**: 프로젝트 계획을 수립하는 단계로, BCP 개발의 명확한 범위·조직·시간·인원 등을 정의
2. **사업영향평가(BIA)**: 개별 업무(사업 단위)를 식별하고 복구 우선순위, 복구 목표 시간 및 수준 등을 평가. 개별 업무 중단 시 재정적 손실 정도를 평가
3. **복구전략개발**: 복구 자원 및 복구 방안들에 대한 평가
4. **복구계획수립**: 실제 복구 계획 수립 및 명시적 문서화
5. **프로젝트 수행 테스트 및 유지보수**: 테스트 및 유지보수 관리 절차 수립

## 7. 공통평가기준(CC: Common Criteria)

> 출제 이유: CC 인증의 4가지 구성 요소(TOE/PP/ST/EAL)의 용어(영문 약어 포함)를 묻는 단답형 문제가 출제되었습니다.

| 항목 | 내용 |
|---|---|
| 정의 | 정보시스템(IT 제품)의 보안성을 평가하기 위한 기준을 정의한 국제 표준(ISO/IEC 15408) |
| 유래 | 미국의 대표적인 보안 인증 TCSEC(Trusted Computer System Evaluation Criteria, 'Orange Book')과 유럽의 대표적인 보안 인증 ITSEC(Information Technology Security Evaluation Criteria)이 통합되어 1999년 국제 표준으로 승인 |
| 목적 | 평가 개념을 정립하고 평가에 필요한 '보안 기능 컴포넌트'와 '보증 컴포넌트'를 정의. 제품의 신뢰성을 보증하는 수준을 차등화하여 제품 사용환경 및 목적에 맞는 평가·인증을 받을 수 있도록 '평가보증등급(EAL)'을 정의 |

**CC 인증의 4가지 구성 요소**

| 구성 요소 | 설명 |
|---|---|
| 평가대상 (TOE: Target of Evaluation) | 정보시스템(IT 제품)의 보안성 평가범위를 정의한 것. 신청기관은 시스템의 보안 기능성 일부 또는 전체를 평가범위로 정할 수 있음 |
| 보호 프로파일 (PP: Protection Profile) | 평가대상(TOE) 유형별 보안 기능 요구사항을 기술한 문서. 특정 제품 구현과 독립적으로 정의되며, 일반적으로 관련 사용자(소비자) 그룹에 의해 특정 목적으로 생성. 제품 개발자는 하나 이상의 PP를 준수하는 제품을 개발할 수 있음 |
| 보안목표 명세서 (ST: Security Target) | 평가대상(TOE)의 세부 보안 기능 요구사항과 구현 내용을 기술한 문서로 평가의 근거로 사용. 특정 회사의 특정 제품의 보안 특징을 서술하고, 평가범위를 정해 이에 대한 보안 기능 요구사항을 정의한 "제품별 세부 평가 기준"을 말하며, 특정 제품 구현에 종속적으로 정의됨 |
| 평가보증등급 (EAL: Evaluation Assurance Level) | 평가대상(TOE)의 보증 수준을 판단하는 척도를 정의한 등급. **EAL1(최저 등급)부터 EAL7(최고 등급)까지 7개 등급**으로 구분되며, 등급이 높아질수록 보증 수준이 높아짐을 의미. 등급이 높아질수록 평가 노력도(범위·상세·엄격)가 증가하여 평가 기간과 비용이 늘어남 |

## 8. 사회공학(Social Engineering) 기법

> 출제 이유: 컴퓨터 기반 사회공학 기법의 대표 유형인 피싱·파밍·스미싱을 묻는 단답형 문제가 출제되었습니다. 3가지 기법의 차이를 정확히 구분해야 합니다.

| 항목 | 내용 |
|---|---|
| 정의 | 사람들 사이의 신뢰 관계를 바탕으로 사람들을 속여 정상적인 보안 절차를 무너트리고 비기술적인 수단으로 정보를 탈취하는 행위 |
| 분류 | 공격 대상에게 어떤 방식으로 접근하는가에 따라 **인간 기반(Human-based) 공격**과 **컴퓨터 기반(Computer-based) 공격**으로 구분 |

**인간 기반(Human-based) 공격**

- 직접적인 접근(Direct Approach): 높은 지위에 있는 사람으로 가장, 긴급한 상황으로 가장 등
- 도청/엿듣기(Eavesdropping)
- 쓰레기통 뒤지기(Dumpster Diving)
- 어깨너머로 훔쳐보기(Shoulder Surfing)

**컴퓨터 기반(Computer-based) 공격**

| 기법 | 어원 | 정의 | 공격 방법 |
|---|---|---|---|
| 피싱(Phishing) | Private data + Fishing | 희생자에게 신뢰할만한 발신자로 위장한 이메일 등을 전송하여, 희생자가 내용에 있는 링크를 클릭하거나 첨부 파일을 실행하면 가짜 사이트(피싱 사이트)로 접속이 유도되어 개인정보·금융정보 등을 탈취 | 희생자에 대한 정보를 수집한 후, 신뢰할만한 발신자로 속인 가짜 이메일을 전송 |
| 파밍(Pharming) | Private data + Farming | 희생자가 정상적인 도메인(URL) 주소를 입력해 접속해도 가짜 사이트(파밍 사이트)로 접속이 유도되어 개인정보·금융정보 등을 탈취 | hosts 파일 변조, 파밍형 악성코드, DNS 스푸핑 공격 등 |
| 스미싱(Smishing) | SMS + Phishing | 휴대폰 SMS를 이용한 피싱 공격. 관심을 가질만한 가짜 메시지(돌잔치 초대장, 청첩장, 쿠폰 발송 등)를 제공한 후, 링크 클릭 시 가짜 사이트로 접속을 유도해 개인정보·금융정보 탈취 또는 소액결제 유발 | 희생자가 관심을 가질만한 가짜 SMS 메시지 전송 |

!!! tip "TIP"
    피싱=이메일, 파밍=정상 URL 입력해도 가짜 사이트로 유도(hosts 변조·DNS 스푸핑), 스미싱=SMS. 3가지 모두 "가짜 사이트(fake site)"로 유도한다는 공통점이 있습니다.

## 9. ISMS-P 관련

> 출제 이유: ISMS-P 인증 체계의 주요 보호 대책과 정보보호 방침 수립 절차가 출제됩니다.

### 9-0. ISMS-P 인증기준 구조 (필수 암기)

| 항목 | 내용 |
|---|---|
| 정의 | 정보보호 및 개인정보보호 관리체계(ISMS-P) 인증제도란 정보보호 및 개인정보보호를 위한 일련의 조치와 활동이 인증기준에 적합함을 한국인터넷진흥원 또는 인증기관이 증명하는 제도 |
| 인증기준 구성 | 크게 **① 관리체계 수립 및 운영(16개)**, **② 보호대책 요구사항(64개)**, **③ 개인정보 처리단계별 요구사항(22개)** 3개 영역에서 총 **102개**의 인증기준으로 구성 |
| ISMS만 인증 시 | 1번·2번 영역 2개 영역에서 **80개** 인증기준 적용 |
| ISMS-P 인증 시 | 3번 영역(개인정보 처리단계별 요구사항)을 포함하여 **102개** 인증기준 모두 적용 |

**관리체계 수립 및 운영(16개)** — 4개 분야로 구성되며, 정보보호 관리체계 운영 동안 **PDCA**(Plan-Do-Check-Act) 사이클에 따라 지속적·반복적으로 실행

| PDCA 단계 | 의미 |
|---|---|
| Plan (계획) | 정보보호 관리체계를 수립하는 단계 |
| Do (실행) | 수립된 체계를 운영하는 단계 |
| Check (점검) | 운영되고 있는 체계를 점검하는 단계 |
| Act (개선) | 점검 결과에 따라 체계를 향상시키는 단계 |

4개 분야: 관리체계 기반 마련 / 위험관리 / 관리체계 운영 / 관리체계 점검 및 개선

### 9-1. 물리적 보호 대책 (25년도 1회)

보호구역 지정 / 출입 통제 / 정보시스템 보호 / 보호설비 운영 / 보호구역 내 작업 통제 / 반출입 기기 통제 / 업무환경 보안

### 9-2. 정보보호 방침 수립 및 이행 (24년도 4회)

| 항목 | 내용 |
|---|---|
| 정보보호 방침 수립 | 정보보호 목표·범위·책임 등을 포함한 Policy 수립 / 관련 법·규제·계약·기술 요구사항 문서화 및 시행 |
| 정보보호 실행계획 수립 | 방침을 토대로 예산·일정 포함 당해 연도 실행계획 수립 / 최고경영층이 승인 → CISO가 매 반기마다 추진 상황 점검 |

### 9-3. CISO 역할과 책임 4가지 (26년도 1회)

1. 정보보호 계획의 수립·시행 및 개선
2. 정보보호 실태와 관행의 정기적인 감사 및 개선
3. 정보보호 위험의 식별·평가 및 정보보호 대책 마련
4. 정보보호 교육과 모의 훈련 계획의 수립 및 시행
